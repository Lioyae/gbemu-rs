# 完整 GB/GBC、卡带、存档与启动器设计

## 目标

把当前 DMG+MBC1 终端模拟器扩展为完整 GB/GBC 模拟器，并增加官方卡带类型、
音频、电池存档、即时存档、ROM 库和终端文件浏览器。

命令行传入 ROM 时直接启动；无参数启动时进入 ROM 库。项目继续使用 Rust、
Ratatui 和 Crossterm，音频后端使用 cpal。

## 当前基线

当前卡带头只识别四个编码：

- `0x00` ROM-only
- `0x01` MBC1
- `0x02` MBC1+RAM
- `0x03` MBC1+RAM+BATTERY

实际控制器只有 ROM-only 和 MBC1。CPU 每次执行完整指令后才统一推进硬件周期，
因此无法表达每个机器周期上的总线访问，Blargg `mem_timing.gb` 当前失败。

## 实施边界

### 硬件模式

- 支持 DMG 和 CGB。
- CGB-only ROM 自动使用 CGB 模式。
- 双模式 ROM 默认使用 CGB，允许用户强制 DMG 或 CGB。
- 普通 GB ROM 默认使用 DMG。
- 可配置 DMG/CGB Boot ROM；缺失时使用对应开机后状态。
- 实现 CGB 双速、VRAM bank、WRAM bank、彩色调色板、HDMA/GDMA、CGB 精灵优先级。

### 卡带

识别 Pan Docs 列出的 28 个官方卡带头编码，实现以下控制器：

- ROM-only、ROM+RAM
- MBC1、MBC2、MMM01
- MBC3 与 RTC
- MBC5 与 Rumble
- MBC6
- MBC7、EEPROM 与加速度计寄存器
- Pocket Camera
- Bandai TAMA5
- HuC1、HuC3

SRAM、EEPROM 和 RTC 完整持久化。Camera、红外、加速度计和震动实现寄存器及
协议兼容层，默认使用稳定的占位输入；后续可接真实设备。

### 音频

- 实现两个方波声道、波形声道、噪声声道。
- 实现长度计数、包络、扫频、混音、NR50/NR51/NR52、Wave RAM 和 CGB PCM 寄存器。
- 核心输出固定采样率立体声样本，cpal 只负责设备选择和播放。
- 支持静音、主音量和音频设备故障后的无声继续运行。

### 电池存档

- 存档位于 ROM 同目录，使用同名 `.sav` 和 `.rtc`。
- 完全手动：`Ctrl+L` 读取，`Ctrl+S` 写入。
- SRAM、EEPROM 或 RTC 发生变化后标记为脏。
- 脏数据退出时显示“保存并退出 / 放弃并退出 / 取消”确认框。
- 原子写入临时文件后替换正式文件，避免中断导致存档损坏。

### 即时存档

- ROM 同目录提供 10 个固定槽位，后缀 `.state0` 至 `.state9`。
- 数字键选择槽位，`F5` 保存，`F9` 读取。
- 状态包含 CPU、总线、PPU、APU、定时器、DMA、卡带控制器和输入状态。
- 文件包含格式版本、ROM SHA-256 和硬件模式；不匹配时拒绝加载。

### ROM 库和文件浏览器

- 无参数启动时显示 ROM 库优先的 TUI。
- 支持配置多个目录并递归扫描 `.gb`、`.gbc`。
- 列表显示标题、DMG/CGB 模式、卡带类型、ROM/RAM 容量和存档状态。
- `F2` 打开终端文件浏览器，允许选择库外 ROM。
- `F5` 刷新目录，支持添加和移除库目录。
- 配置保存在用户配置目录，不依赖程序当前工作目录。

## 架构

### 周期调度

CPU 改为以机器周期为最小推进单位。每个取指、读、写、内部等待和中断步骤都调用
总线周期接口。总线在每个周期推进 PPU、APU、Timer、OAM DMA、HDMA 和串口。
CGB 双速只改变 CPU 与部分总线设备的相对推进，不改变 PPU/APU 基准频率。

### 模块边界

- `cpu/`：指令微操作与中断状态机。
- `bus/`：地址路由、硬件模式、DMA 和周期协调。
- `ppu/`：DMG/CGB LCD 时序、FIFO、调色板和帧缓冲。
- `apu/`：四声道生成、帧序列器和采样缓冲。
- `audio/`：cpal 输出线程，不包含硬件规则。
- `cartridge/`：卡带头、控制器、持久化数据和外设占位接口。
- `save/`：电池存档、RTC 文件、即时状态格式和原子写入。
- `library/`：配置、目录扫描、ROM 元数据和文件浏览状态。
- `tui/`：启动器、游戏、调试器、存档确认框。

### 序列化

硬件状态使用显式、版本化的数据结构，不直接序列化运行时线程、文件句柄或 cpal 对象。
音频设备和 TUI 在读取即时状态后继续使用当前运行时资源。

## 错误处理

- 无法解析的 ROM 在库中标记错误，不阻断其他文件扫描。
- 已识别但尚未正确配置的卡带给出卡带编码、声明容量和具体原因。
- Boot ROM 长度或模式错误时拒绝使用，并允许用户改为跳过 Boot ROM。
- 音频初始化失败时显示警告并进入静音模式。
- 存档校验、版本或 ROM 哈希不匹配时不修改当前模拟器状态。

## 测试与验收

- 单元测试覆盖卡带头、每种 MBC、RTC、EEPROM、存档格式、库扫描和模式选择。
- CPU/总线重构后要求现有 11 个 CPU ROM 与组合 `cpu_instrs.gb` 继续通过。
- `mem_timing.gb` 作为机器周期重构验收目标。
- 使用公开 DMG/CGB CPU、PPU、Timer、DMA、APU 和 MBC 测试 ROM 分阶段验收。
- ROM 库和文件浏览器使用纯状态测试；终端绘制使用固定区域快照或结构断言。
- 每个里程碑独立提交；只在大里程碑结束时执行完整格式、Clippy、测试和 Release 构建。

## 非目标

- 不实现网络联机或实体 Link Cable。
- 不直接访问真实相机、红外、加速度计或震动设备。
- 不实现 SGB 边框和 SGB 主机功能。
- 不附带商业 ROM 或版权 Boot ROM。
